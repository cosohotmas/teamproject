## 🔴 3. 프로젝트 제약 사항 및 안티 패턴 배제 (Don't Do)

가이드라인 준수 및 감점 요인의 원천 차단을 위해 아래 기술 및 방식은 설계 단계부터 철저히 배제했습니다.

* **❌ 오케스트레이션 프레임워크 사용 금지**: LangChain, LangGraph 등의 라이브러리를 사용하지 않고, **순수 코드 레벨(Pure Code)에서 에이전트의 흐름을 직접 제어**합니다.

* **❌ 무분별한 기능 확장 지양**: "기능이 많을수록 좋다"는 오류에서 벗어나, 매장 소음과 하드웨어 지연 시간이라는 물리적 제약을 고려하여 **필요 없는 기능을 과감히 덜어내고 핵심 기능의 무결성을 확보**했습니다.

본 단계에서는 가상의 실험실 환경이 아닌, 실제 1인 자영업 매장의 극한 환경을 정량적 데이터로 정의하여 시스템의 물리적 한계를 명확히 규정합니다.

### 1. 극사실적 사용자 페르소나 (Persona)
* **이름 / 연령**: 김민지 (34세, 여성)
* **운영 업종**: 1인 운영 수제 브런치 & 에스프레소 바 (홀 좌석 4개, 테이크아웃 위주)
* **행동 패턴**: 피크 타임(11:30 ~ 13:30)에 주문이 몰리면 양손에 니트릴 장갑을 착용한 채로 에스프레소 추출, 스팀, 샌드위치 조리를 동시에 진행함. 가스레인지 불 앞이나 싱크대 앞에서 몸을 돌리기 어려운 상태가 평균 3분~5분간 지속됨.
* **기술 수용도**: IT 기기 사용에 능숙하지 않으며, 조리 중 화면을 터치하거나 복잡한 텍스트 리스트를 읽을 여유가 전혀 없음. 소리로 인지하고 음성으로 통제하는 직관적 인터페이스가 필수적임.

### 2. 주방 내부 소음 환경 데이터 (Acoustic Environment)
매장 내 소음은 STT(Faster-Whisper)의 오인식률(WER)에 직접적인 영향을 미치므로, 상시 소음과 간헐적 피크 소음을 실측 데이터 기반으로 세분화하여 모델 입력 제약을 수립합니다.

* **상시 백색 소음 ($65\,\text{dB} \sim 68\,\text{dB}$)**: 대형 상업용 주방 환풍기(덕트) 가동 소음, 냉장고 컴프레서 구동음.
* **간헐적 임펄스성 소음 ($75\,\text{dB} \sim 82\,\text{dB}$)**: 에스프레소 머신 우유 스팀 작업($78\,\text{dB}$), 가스레인지 불꽃 점화 및 조리 도구 마찰음($75\,\text{dB}$), 믹서기 및 그라인더 원두 분쇄 소음($82\,\text{dB}$).
* **시스템 대응 제약**: 음성 인식을 시작하는 기준점인 **VAD(Voice Activity Detection)의 임계값(Threshold)**을 최소 `0.55` 이상으로 상향 피팅하지 않으면, 주방 소음을 사람의 음성으로 오인식하여 무한 루프가 발생할 수 있는 물리적 한계 확인.

---

### 3. 하드웨어 및 통신 환경 제약 (Hardware & Network)
* **엣지 디바이스 (매장 입구 호스트)**: 매장에서 굴러다니는 구형 아이패드 6세대 또는 안드로이드 보급형 태블릿 (인공지능 연산 불가능, 오직 마이크 입출력 및 화면 렌더링용 IO 장치로 한정).
* **AI 백엔드 인프라**: 외부 유료 클라우드(AWS, GCP) 비용 부담을 제거하기 위해 무료 티어 기반 배포(Hugging Face Spaces) 환경을 채택함. 단, 무료 CPU 환경의 연산 병목을 방지하기 위해 가중치 양자화 및 스트리밍 처리 필수.
* **네트워크 지연 (Latency Boundary)**: 매장 내 공유기(Wi-Fi 5 환경)의 업/다운로드 대역폭 변동성을 고려하여, 음성 패킷 chunk 단위를 **0.5초(소형 버퍼)**로 쪼개어 백엔드로 전송해야 네트워킹 타임아웃을 방지할 수 있음.

* **전환**: 카운터 앞 **특정 바운딩 박스 영역에 손님이 진입하는 최초 0.5초의 순간에만 1회 트리거**되어 인사를 건네는 확실하고 직관적인 구조로 UX를 재설계했습니다.

## 📐 3. 하드웨어 제약 극복을 위한 공학적 튜닝 (원칙 1, 5 저격)

"내 컴퓨터에서는 잘 된다"는 데모 수준에 머물지 않고, 기기마다 성능이 다른 환경적 문제를 '설계의 입력값'으로 흡수했습니다.

* **상용 API(ElevenLabs) 배제 근거**: 8장 비교 실험 결과, 상용 API는 뛰어난 음질을 보였으나 네트워크 통신 오버헤드로 인해 첫 패킷 도달 시간(TTFB)이 1.5초를 초과했습니다. 손님을 1초 내에 붙잡아야 하는 매장 제약 조건을 충족하기 위해, 통신 지연이 없는 **로컬 오픈소스 경량 모델(`F5-TTS/Kokoro`)을 최종 낙점**했습니다.
* **자체 딥러닝 가속 (INT8 양자화)**: 서버와 기기의 자원 한계를 흡수하기 위해 오픈소스 모델 로드 시 **`compute_type="int8"` 가속 옵션을 코드 레벨에서 직접 제어**했습니다. 가중치 용량을 4분의 1로 압축하여 **최종 RTF(실시간 지표) 0.38**을 달성했습니다.
* **우아한 Fallback(실패 가드레일) 구현**: 매장 와이파이가 일시 단절되거나 서버 다운으로 딥러닝 추론이 실패할 경우(`try-except`), 앱이 멈추거나 뻗지 않고 **로컬 캐시 폴더에 내장된 기본 안내 음성 파일(`"잠시만기다려주세요.mp3"`)을 즉시 호출해 출력**하는 복구 탄력성을 백엔드 단에 하드코딩했습니다.
